--- layout: base.html permalink: /search/ title: "Search @imqueue" description: "Search every @imqueue guide, article and API symbol — full text, in your browser, with no server involved." noindex: true nofollow: true eleventyExcludeFromCollections: true --- {%- comment -%} The full result list, paged. The dialog (⌘K anywhere on the site) shows the best ten per group, which is the right size for "find the page I mean"; this is the other job — see everything that matched and walk it. At src/ root rather than src/org/, so BOTH editions build it. imqueue.com needs one for the same reason it needs a search box at all: the "All N results" link the dialog shows points at `/search/` on the current origin, and on com that was a 404 — the dialog offered a page that did not exist. Its results are com's seven pages plus the documentation from imqueue.org in a group of their own. `base.html` rather than `docs.html`: a docs page brings an "On this page" sidebar built from headings this page has none of, a markdown-mirror link to a mirror that does not exist, and a "last updated" date that means nothing for a page whose content is a query result. `noindex` + `nofollow` + `eleventyExcludeFromCollections`: a search-results page must never be in an index of its own site, and its links are not endorsements — the URL space is unbounded (`?q=` accepts anything) and every result it shows is reachable from a real page. head.html carries the matching X-Robots-Tag reasoning. Between them this page stays out of the sitemap, out of llms.txt, out of the search index and out of SERPs — while remaining perfectly fetchable, which is what /search/?q= needs to be for the WebSite SearchAction in head.html to be a true claim. Everything below is empty on purpose. src/org/js/search.js fills it, running the same ranker over the same two index files the dialog uses — one implementation, so the dialog and this page cannot disagree about what matches. {%- endcomment -%}
