--- layout: base.html permalink: /search/ title: "Search the @imqueue documentation" description: "Search every @imqueue guide, article and API symbol — full text, in your browser, with no server involved." noindex: true eleventyExcludeFromCollections: true --- {%- comment -%} The full result list, paged. The dialog (⌘K anywhere on the site) shows the best ten per group, which is the right size for "find the page I mean"; this is the other job — see everything that matched and walk it. `base.html` rather than `docs.html`: a docs page brings an "On this page" sidebar built from headings this page has none of, a markdown-mirror link to a mirror that does not exist, and a "last updated" date that means nothing for a page whose content is a query result. `noindex` + `eleventyExcludeFromCollections`: a search-results page must never be in an index of its own site. Between them this page stays out of the sitemap, out of llms.txt, out of the search index and out of SERPs — while remaining perfectly fetchable, which is what /search/?q= needs to be for the WebSite SearchAction in head.html to be a true claim. Everything below is empty on purpose. src/org/js/search.js fills it, running the same ranker over the same two index files the dialog uses — one implementation, so the dialog and this page cannot disagree about what matches. {%- endcomment -%}
