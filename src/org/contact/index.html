Where else to go

Some things get a faster answer somewhere else:

  • A bug or a feature request — file it in the package's own repository, which is where its maintainers are looking. See Support for which repo covers what.
  • A security vulnerability — please do not use this form or a public issue. Use GitHub's private advisory channel on the affected repository, or email support@imqueue.com directly.
  • A commercial licence or an SLA — the enquiry form on imqueue.com asks the questions needed to scope one.
  • A question others would benefit from — a GitHub issue is public and searchable, so the next person with your problem finds the answer.

What happens to what you send

It is emailed to the maintainers and nothing else: no ticketing system, no CRM, no mailing list. Attachments travel with it. Full detail — the fields, the mail provider, how long it is kept — is in the privacy policy.

Please don't paste credentials, connection strings or customer data. If you need to send something sensitive, say so and we'll arrange a better channel.
