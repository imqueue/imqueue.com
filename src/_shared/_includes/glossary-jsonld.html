{%- comment -%} DefinedTermSet markup, generated from the page's own `### Term` entries. See the definedTerms filter in eleventy.config.js for the parsing rules. Opt-in per page via `definedTermSet: true` in front matter, rather than applied to every docs page: a `### `-heavy reference page is not a glossary, and emitting DefinedTerm for its section titles would assert that they are vocabulary. Only /glossary/ sets it today. Each term gets a stable `@id` from its own heading anchor, so the node an engine resolves and the fragment a human lands on are the same URL. The anchor is built with the `mdSlug` filter — the very function markdown-it-anchor uses to write the `id` attribute — rather than Eleventy's built-in `slug`, which keeps characters this site's slugifier drops. An independently-computed slug here would mint edges pointing at fragments that do not exist. `inDefinedTermSet` is the reciprocal of the set's `hasDefinedTerm`; both are emitted because engines follow the edges in different directions. {%- endcomment %} {%- if definedTermSet -%} {%- assign termList = page.rawInput | definedTerms -%} {%- if termList.size > 1 -%} {%- capture pageUrl -%}{{ siteUrl }}{{ page.url }}{%- endcapture -%} {%- assign setId = pageUrl | append: "#terms" -%} {%- endif -%} {%- endif -%}
